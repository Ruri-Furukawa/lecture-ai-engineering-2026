## 宿題

- 取り組んだレベル：基礎
- やったこと：`gemini-3.5-flash-lite` と `gemini-3.5-flash` の2つのモデルに、「LoRAとは何ですか？」という同じ質問を3回ずつ行い、回答の内容と出力トークン数を比べた。実行したコマンドは `AIE_MODEL=gemini-3.5-flash-lite uv run python -m app.ask` "LoRAとは何ですか？" と `AIE_MODEL=gemini-3.5-flash uv run python -m app.ask` "LoRAとは何ですか？" で、演習6で追加したトークン数の表示を使って、各回の入力・出力トークン数を記録した。
- 結果：入力トークン数はどの回も7で同じだった。出力トークン数は、flash-liteが573・595・490（平均約553）、flashが706・639・698（平均約681）で、flashの方が平均で2割ほど長かった。中身の骨格は全6回で共通していて、「Low-Rank Adaptationの略」「元の重みを固定し、小さな追加パラメータだけを学習する」「低コスト・ファイルが軽い・切り替えが簡単」「画像生成AIとLLMで使われている」という流れだった。一方で、たとえ（「小さなパーツ」「付箋」「透明なシート」「プラグイン」など）や見出しの構成は毎回変わった。細かい数値も回によって揺れ、flash-liteでは学習するパラメータの割合が「1%未満」の回と「数%程度」の回があり、LoRAファイルのサイズも「数十MB〜数百MB」の回と「数MB〜数十MB」の回があった。flashは「Microsoftの研究者が提案」「複数のLoRAを組み合わせられる」「無線通信のLoRaとは別物」といった補足や具体例が多かったが、3回目には「数MB〜数億MB」という明らかに誤った記述も含まれていた。
- 気づき・疑問：同じモデルに同じ質問をしても、表現や細かい数値は毎回変わることが分かった。大まかな説明は信頼できても、具体的な数字はそのまま信じず、論文などの一次情報で確かめる必要があると感じた。大きいモデル（flash）は補足が多く分かりやすかった反面、出力トークンが多いぶん、コストや応答時間、無料枠のレート制限には不利になると考えられる。また、どちらのモデルも、名前の由来である「低ランク」の仕組み（重みの変化を2つの小さな行列の積で表すこと）にはほとんど触れず、比喩ばかりの説明だった。LoRAは一般的な用語なので6回とも大筋は正しかったが、演習で試した講座固有の質問では作り話をしていたことを考えると、正しさは「モデルがその知識を持っているか」に強く左右されると思う。疑問として、temperatureを下げれば回答の揺れ（特に数値の揺れ）はどの程度おさまるのかを確かめてみたい。
